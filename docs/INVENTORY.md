This file records what exists, what is real, and what is not built yet. The **SIMULATED register** (Section 1.2) must list every simulated item in the repository. Remove an entry only in the commit that removes the simulation.

## 1. Summary

The current repository is one Next.js 14 app (npm, no monorepo). It has a polished dark UI, a 3D hero and a 6-stage "pipeline canvas". **There is no engine.** The app has no OpenAPI parser, diff, traffic handling, validation or classification of real changes. Every analysis result on screen is a hardcoded array revealed on a `setTimeout`. Several API routes authenticate unauthenticated callers as a demo user. A live API key for a third-party LLM service is hardcoded in an untracked source file.

The reviewers' "vibe coded" criticism holds for everything the product shows about analysis. Auth, Prisma and the webhook HMAC check are the only parts that do real work, and each has defects (Section 5).

## 5. Security findings to act on before or at M0

1. **Hardcoded Groq API key** in `app/api/ai/chat/route.ts:55` (untracked, so not in local git history). **Rotate the key in the Groq console now**, whatever else we decide. It may have been deployed or shared outside this checkout, and it sits in plaintext in the working tree. Delete the literal, and never commit this file as is.
2. Demo-user fallback in `authenticateApiRequest` is on by default, including production.
3. Dev "log in as anyone" in `lib/auth.ts`.
4. Unauthenticated, unscoped `GET /api/projects` and `GET /api/reports`, and unauthenticated `POST /api/projects`, `/api/keys`, `/api/upload`, `/api/ai/chat`.
5. In-memory rate limiting.
6. `lib/env.ts` falls back to raw `process.env` when validation fails outside development, so invalid config silently boots in production.

If the old app is still deployed (README mentions `driftapi.vercel.app`), items 2–4 are live there. Consider taking it down or setting `NEXT_PUBLIC_ENABLE_DEMO_MODE=false` until the rebuild replaces it.
